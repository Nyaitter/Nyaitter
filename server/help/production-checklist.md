# 本番デプロイのチェックリスト

Nyaitter を公開環境へ出す前後に確認する項目です。チェックリストは環境ごとに記録し、変更時には再実施してください。

## 1. デプロイ前

### 実行環境と認証

- [ ] `NODE_ENV=production` を設定した。
- [ ] `DEV_BYPASS_AUTH` は未設定または `false` である。**公開サーバーで `true` にしない。**
- [ ] `MULTI_ACCOUNT_COOKIE_SECRET` と `LOGIN_SECURITY_HMAC_SECRET` に十分に長い固定ランダム値を設定した。
- [ ] Turnstileを使う場合、`TURNSTILE_SECRET_KEY` とフロントエンド用サイトキーを本番用に設定した。
- [ ] セッションCookieが HTTPS で安全に送受信される構成を確認した。

### リバースプロキシとネットワーク

- [ ] 信頼できるリバースプロキシの背後でのみ `TRUST_PROXY=true` を設定した。
- [ ] TLS終端、転送ヘッダー、クライアントIP、WebSocketのUpgrade転送を確認した。
- [ ] 公開URL、CORS許可オリジン、外部ログインの federation 設定を環境に合わせた。
- [ ] WebSocket接続がCDN・ロードバランサーのタイムアウトで切断されないことを確認した。

### データベース

- [ ] `DB_ADAPTER=postgres` または `DB_ADAPTER=d1` を選択し、InMemoryAdapterを使っていない。
- [ ] DB接続情報はシークレット管理へ保存し、Git・ログ・クライアントへ出していない。
- [ ] 必要なマイグレーションを番号順に適用した。
- [ ] バックアップ、復旧、ロールバックの手順を確認した。
- [ ] PostgreSQLではSSL、接続プール、最大接続数を確認した。
- [ ] D1では Worker の `AUTH_TOKEN` と `D1_WORKER_TOKEN` が一致し、未認証リクエストが拒否されることを確認した。

### ストレージとPush

- [ ] 実運用の添付保存先を設定した。ローカルストレージを使う場合は永続ボリュームとバックアップを用意した。
- [ ] R2を使う場合、バケット、権限、公開ドメインまたは署名URLの方式を確認した。
- [ ] `STORAGE_USER_QUOTA_MB` を運用に合うMB単位の値へ設定し、ユーザー別の保存上限を確認した。
- [ ] 画像のEXIF削除・圧縮後のサイズ判定と、ファイル一覧・削除操作を確認した。
- [ ] `VAPID_SUBJECT`、`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY` を安定して保存した。
- [ ] 秘密鍵・トークン・`server/.env` が追跡対象外であることを確認した。

### HTTP・キャッシュ・監視

- [ ] `LOG_LEVEL`、エラーログの収集先、`x-request-id` を確認した。
- [ ] `/server/health` と `/server/ready` を監視対象に設定した。
- [ ] 静的資産が再検証可能なキャッシュヘッダーで配信され、変更後に更新されることを確認した。
- [ ] サービスワーカー更新後に新しいクライアント資産が取得されることを確認した。
- [ ] レート制限が有効で、特に `/server/auth/*` の上限が環境に適していることを確認した。
- [ ] CSPとリファラーポリシーが配信され、外部ログインの遷移先が意図したサーバーに限定されることを確認した。

## 2. デプロイ後のスモークテスト

- [ ] `GET /server/health` が 200 を返す。
- [ ] `GET /server/ready` が 200 を返す。
- [ ] Scratch認証または設定したログイン方式で認証できる。
- [ ] 投稿、返信、引用、いいね、スター、リポスト、検索、添付アップロードが動作する。
- [ ] 設定 → ストレージで使用率・ファイル一覧が表示され、上限超過時のアップロードが拒否される。
- [ ] フォロー、通知、Web Push、グループDM、DM未読数、リアルタイム接続が動作する。
- [ ] 投稿者のフォロワーだけにリアルタイム投稿通知が届く。
- [ ] 非公開投稿、検索除外、ブロック関係の可視性がタイムライン、検索、おすすめ、詳細、プロフィール、通知、DMで一貫する。
- [ ] ブロック関係にある利用者をDMへ招待できず、既存会話の相手メッセージ・未読数が見えない。
- [ ] 連続リクエストに対してレート制限が 429 を返す。
- [ ] ブラウザ更新後に古いJS/CSSが残らず、主要画面が描画される。

## 3. 継続運用

- [ ] DB・ストレージ・Worker・Node.jsのエラー率と応答時間を監視する。
- [ ] PostgreSQLのバックアップ、R2の保持方針、D1のエクスポートを定期的に確認する。
- [ ] 依存関係、OS、Node.js、Wranglerを定期更新する。
- [ ] マイグレーション前にステージング検証とバックアップを行う。
- [ ] シークレットを定期ローテーションし、漏えい時の失効手順を準備する。
- [ ] DM、通知、投稿の可視性に影響する変更は、複数アカウントで回帰確認する。

## 本番でしてはいけないこと

- `DEV_BYPASS_AUTH=true` を設定する。
- InMemoryAdapterを本番データの保存先として使う。
- DB/R2/D1/VAPIDの秘密情報をコード、`config.json`、クライアント、ログへ含める。
- `TRUST_PROXY=true` を、信頼できない直接公開構成で有効にする。
- Workerの `AUTH_TOKEN` を未設定・共有・弱い値のまま運用する。
- バックアップ・復旧の確認なしに破壊的マイグレーションを適用する。
